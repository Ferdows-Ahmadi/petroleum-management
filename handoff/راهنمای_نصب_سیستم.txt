روش ساده نصب نخست: بسته ZIP را در یک فولدر دایمی باز کنید و روی FIRST_SETUP.bat دو بار کلیک کنید. FIRST_SETUP.ps1 به صورت داخلی اجرا می‌شود. نصب موفق قبلی را دوباره نصب نکنید؛ برای کار روزانه میانبر سیستم را باز کنید.

راهنمای نصب نفت‌یار ـ برای نصب‌کننده تخنیکی
نسخه تحویلی شرکت ـ 2026-10-03

1. هدف
این بسته برای نصب تازه است. کارمندان پس از نصب فقط مرورگر و حساب کاربری لازم دارند. بسته شامل vendor و فایل‌های ساخته‌شده رابط است؛ برای اولین اجرا Composer، Node یا npm لازم نیست.
نصب روی کمپیوتر اصلی شرکت انجام می‌شود. هیچ دیتابیس یا معلومات شرکت پیشین را پاک نکنید.

روش پیشنهادی نصب هدایت‌شده:
پس از نصب پیش‌نیازهای بخش ۲، ZIP را باز کنید و یک بار اجرا کنید:
powershell -NoProfile -ExecutionPolicy Bypass -File .\FIRST_SETUP.ps1
این برنامه مسیر ابزارها و نام/کاربر/رمز دیتابیس را می‌پرسد؛ رمزها مخفی‌اند. فقط دیتابیس تازه و خالی پذیرفته می‌شود. در صورت نیاز، رمز مدیر محلی MySQL را برای ساخت schema خالی و حساب اختصاصی با دسترسی محدود به همان schema می‌پرسد؛ رمز مدیر ذخیره نمی‌شود و رمز حساب موجود تغییر نمی‌کند.
نام و ایمیل مدیر عمومی و رمز تازه حداقل ۱۲ حرف با حروف بزرگ/کوچک انگلیسی و عدد را وارد کنید. هیچ معلومات نمایشی نصب نمی‌شود. APP_KEY، migrations و بررسی نصب خودکار انجام می‌شوند؛ vendor و رابط از بسته آماده‌اند.
اگر .env یا دیتابیس غیرخالی وجود داشته باشد، برنامه نصب مجدد را رد می‌کند؛ هرگز برای گذر از این مانع معلومات شرکت را پاک نکنید. اگر نصب نیمه‌کاره ماند، مرحله خطا نشان داده می‌شود؛ نصب‌کننده همان نصب را مطابق روش دستی زیر بررسی و تکمیل کند.
دو میانبر روی Desktop کاربر نصب‌کننده ساخته می‌شوند: «سیستم مدیریت شرکت» و «پشتیبان سیستم شرکت». START_SYSTEM.bat و BACKUP_SYSTEM.bat کار روزانه را انجام می‌دهند. فایل .company-runtime.json فقط مسیر ابزارها و آدرس محلی را نگه می‌دارد؛ رمز در آن نیست. .env و Backups با دسترسی همان کاربر Windows، مدیران و SYSTEM محافظت می‌شوند. روی حساب Windows دیگری، نصب‌کننده دسترسی لازم/وب‌سرور را تنظیم کند؛ کارمند تنظیمات را تغییر ندهد.
شروع روزانه روی همین کمپیوتر است؛ مرورگر خودکار باز و اجرای پس‌زمینه پس از بسته‌شدن پنجره ادامه دارد. کلیک دوباره همان اجرای سالم را باز می‌کند. هنگام خاموش/روشن‌شدن کمپیوتر، کلیک میانبر کافی است؛ سرویس MySQL باید شروع خودکار داشته باشد. پورت مصروف متعلق به برنامه دیگر گرفته/متوقف نمی‌شود.
در تمرین نصب، نصب‌کننده می‌تواند مسیر فولدر موجود مخصوص میانبرهای آزمایشی را با گزینه -ShortcutDirectory به FIRST_SETUP.ps1 بدهد. در نصب عادی میانبرها روی Desktop ساخته می‌شوند.
پیش از توقف برای نگهداری، از کارمندان بخواهید ثبت را تکمیل کنند و از سیستم خارج شوند. در فولدر همین نصب STOP_SYSTEM.bat را برای توقف سرور محلی و RESTART_SYSTEM.bat را برای راه‌اندازی مجدد باز کنید. این دو فرمان مالکیت پروسه را بررسی می‌کنند. اگر پورت از برنامه دیگری باشد، CHECK_SYSTEM.bat را اجرا کنید و راپور را به نصب‌کننده بدهید. سرویس IIS/Apache شبکه به روش جداگانه اداره می‌شود.
پشتیبان یک‌کلیکی در Backups/backup-تاریخ-ساعت ذخیره و فولدر خودکار باز می‌شود؛ دیتابیس و فایل‌های خصوصی/عمومی را دارد. رمز نصب داخلی استفاده می‌شود و از کارمند پرسیده نمی‌شود. پشتیبان شامل .env و APP_KEY نیست؛ نسخه محفوظ کلید و تنظیمات را نصب‌کننده جدا نگه دارد. از Backups روی رسانه جدا و محفوظ نیز نسخه بگیرید.
فولدر نصب را پس از ساخت میانبر جابه‌جا نکنید. برای تعمیر میانبر بدون تغییر دیتابیس: فایل handoff/OPERATIONAL_COMMON.ps1 را dot-source و New-CompanyShortcuts را اجرا کنید؛ ابتدا میانبر نصب قدیمی را با نام دیگر محفوظ کنید.
کارمندان فقط راهنمای_خیلی_ساده_کاربران.txt را بخوانند. روش دستی مفصل زیر برای نگهداری باقی مانده است.

2. پیش‌نیازها
Windows 64-bit پشتیبانی‌شده؛ PHP 8.5.x 64-bit؛ MySQL Community Server 8.4.x همراه ابزارهای mysql و mysqldump. نسخه آزمایش‌شده PHP 8.5.0 و MySQL 8.4.11 است. PHP 8.3 برای این بسته مناسب نیست.
برای PHP رسمی Windows، Visual C++ Redistributable 2015–2022 x64 لازم است. MySQL 8.4 به Visual C++ 2019 نیاز دارد که نسخه سازگار 2015–2022 x64 آن را پوشش می‌دهد.
منابع رسمی:
https://www.php.net/manual/en/install.windows.manual.php
https://www.php.net/downloads.php?os=windows
https://dev.mysql.com/doc/refman/8.4/en/windows-installation.html
افزونه‌های لازم:
bcmath, ctype, date, dom, fileinfo, filter, hash, iconv, json, libxml, mbstring, openssl, pcre, PDO, pdo_mysql, Phar, session, SimpleXML, tokenizer, xml, xmlwriter
برخی در PHP داخلی هستند. OPcache برای استفاده دوامدار توصیه می‌شود. pdo_sqlite تنها برای آزمون تکمیلی برنامه‌نویس است. mysql و mysqldump را به PATH اضافه کنید.
در PowerShell بررسی کنید:
php -v
php -m
mysql --version
mysqldump --version

3. جای‌گذاری
ZIP را در فولدر انتخاب‌شده، مانند C:\CompanySystem\petroleum-management، باز کنید. مسیر می‌تواند متفاوت باشد. بسته به مسیر کمپیوتر سازنده وابسته نیست.
فایل‌های artisan، vendor\autoload.php و public\build\manifest.json باید موجود باشند.
PowerShell را در همین فولدر باز کنید. فرمان‌های زیر از ریشه همین فولدر اجرا می‌شوند.
اگر اجرای اسکریپت‌های محلی بسته است، آن‌ها را ابتدا بررسی کرده و برای همان اجرا از این روش استفاده کنید:
powershell -NoProfile -ExecutionPolicy Bypass -File .\CHECK_REQUIREMENTS.ps1 -Offline
این فرمان پالیسی عمومی Windows را تغییر نمی‌دهد.

4. MySQL و دیتابیس تازه
MySQL را با MSI رسمی نصب و در MySQL Configurator به صورت Windows Service با شروع خودکار تنظیم کنید. رمز مدیر MySQL را محفوظ نگه دارید؛ آن را رمز برنامه قرار ندهید.
دیتابیس خالی با نام انتخاب‌شده، مثلاً petroleum_management، با utf8mb4 و utf8mb4_unicode_ci بسازید.
در MySQL Workbench یا ابزار مدیریتی، حساب جداگانه مثلاً petroleum_app را فقط برای همین دیتابیس ایجاد کنید. رمز تازه و قوی انتخاب کنید؛ رمز را در راهنما یا اسکریپت ذخیره نکنید.
برای اتصال محلی حساب را به localhost محدود کنید. دیتابیس روی 127.0.0.1 و پورت 3306 بماند؛ پورت MySQL را برای کارمندان شبکه باز نکنید.
صلاحیت نصب و نگهداری فقط روی دیتابیس برنامه:
SELECT, INSERT, UPDATE, DELETE, CREATE, ALTER, DROP, INDEX, REFERENCES, CREATE TEMPORARY TABLES
هیچ صلاحیت سراسری، GRANT OPTION، FILE، PROCESS، SUPER یا ایجاد دیتابیس برای حساب برنامه لازم نیست.
بعد از اجرای migrations، مدیر MySQL می‌تواند CREATE, ALTER, DROP, INDEX, REFERENCES و CREATE TEMPORARY TABLES را از حساب اجرای روزانه بردارد. برای تغییرات ساختار بعدی از حساب نصب‌کننده محدود به همین دیتابیس استفاده شود.
مدیر MySQL فقط این مرحله را انجام می‌دهد. DB_USERNAME در برنامه هرگز root نباشد.
برای ساخت دیتابیس و اعطای صلاحیت، این الگوی بدون رمز واقعی قابل استفاده است:
CREATE DATABASE petroleum_management CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
پس از ساخت حساب از صفحه Users and Privileges، صلاحیت‌های بالا را فقط برای همین schema بدهید. رمز را در بخش Password ابزار وارد کنید، نه در فرمان یا متن قابل اشتراک.

5. فایل تنظیمات
Copy-Item .env.example .env
فایل .env را با ویرایشگر محلی باز کنید. این فایل خصوصی است؛ در ایمیل، ZIP عمومی یا Git قرار ندهید.
مقادیر لازم:
APP_NAME="نفت‌یار"
APP_ENV=production
APP_DEBUG=false
APP_URL=http://127.0.0.1:8080
DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=نام_دیتابیس_تازه
DB_USERNAME=نام_حساب_جداگانه
DB_PASSWORD="رمز_تازه_همان_حساب"
رمز نمونه بالا فقط جای‌نگهدار است؛ رمز آماده وجود ندارد. اگر رمز شامل علامت خاص است، آن را مطابق فایل .env داخل نقل‌قول درست بنویسید.
SESSION_DRIVER=database
SESSION_ENCRYPT=true
SESSION_HTTP_ONLY=true
SESSION_SAME_SITE=lax
CACHE_STORE=file
QUEUE_CONNECTION=sync
برای HTTP محدود شبکه داخلی SESSION_SECURE_COOKIE=false است. وقتی HTTPS تنظیم شد آن را true کنید و APP_URL را به آدرس HTTPS تغییر دهید.
زمان سیستم Asia/Kabul است. تاریخ قابل مشاهده هجری شمسی و ارقام وزن/پول غربی‌اند. Windows باید ساعت درست داشته باشد.

6. کلید و نصب ساختار
php artisan key:generate
php artisan config:clear
php artisan migrate --force
نصب فعلی باید 19 migration اجرا کند. شمار دقیق در manifest نسخه درج می‌شود.
db:seed برای شروع کار شرکت لازم نیست؛ هیچ مشتری، عرضه‌کننده، معامله یا کاربر نمونه نصب نمی‌شود.
هرگز migrate:fresh یا db:wipe روی دیتابیس موجود شرکت اجرا نکنید.
اگر رمز/حساب دیتابیس اشتباه است، ابتدا تنظیمات را اصلاح کنید؛ دیتابیس دیگری را برای رفع خطا پاک نکنید.

7. مدیر عمومی اول
php artisan app:create-manager --name="مدیر عمومی"
نام مدیر را در بخش name با نام واقعی جایگزین کنید؛ این روش از مشکل تبدیل حروف دری در بعضی کنسول‌های Windows جلوگیری می‌کند. ایمیل شخصی مدیر و رمز تازه را در پرسش‌های فرمان وارد کنید. رمز و تأیید آن مخفی دریافت می‌شوند.
رمز حداقل 12 حرف، حروف بزرگ/کوچک و عدد داشته باشد. هیچ رمز مدیر آماده در بسته نیست.
فرمان پس از وجود مدیر عمومی فعال دوباره مدیر نمی‌سازد. مدیر پس از ورود می‌تواند کاربران مجاز را از تنظیمات بسازد.

8. اجازه فولدرها
حساب Windows که PHP را اجرا می‌کند باید اجازه نوشتن/تغییر روی storage و bootstrap\cache داشته باشد. به همه افراد شبکه اجازه کامل ندهید.
اسناد خصوصی در storage\app\private نگهداری می‌شوند. public تنها ریشه وب‌سرور است. هیچ وقت ریشه کل برنامه یا storage خصوصی را به عنوان فولدر وب منتشر نکنید.
storage:link برای تکت خصوصی لازم نیست. فایل .env و vendor نباید از مرورگر قابل دریافت باشند.
php artisan app:check-system
این بررسی معلومات تجارتی را تغییر نمی‌دهد؛ فقط اتصال، فایل‌ها و اجازه نوشتن را بررسی می‌کند.

9. شروع ساده و ورود
powershell -NoProfile -ExecutionPolicy Bypass -File .\START_SYSTEM.ps1
در مرورگر باز کنید:
http://127.0.0.1:8080
با ایمیل و رمز مدیر ساخته‌شده وارد شوید. پنجره اجرای سیستم را باز نگه دارید.
برای توقف، در همان پنجره Ctrl+C را فشار دهید. از بستن تمام پروسه‌های php یا mysql خودداری کنید.
پس از تغییر .env سرور را متوقف کنید، php artisan config:clear را اجرا کنید و دوباره شروع کنید.

10. استفاده شبکه داخلی
روی کمپیوتر میزبان ipconfig را اجرا کنید و IPv4 کارت شبکه شرکت را بخوانید. آدرس ثابت/رزرو DHCP با مسئول شبکه تنظیم شود.
APP_URL را به http://آدرس_میزبان:8080 تغییر دهید، تنظیمات cache را پاک کنید و سیستم را چنین اجرا کنید:
powershell -NoProfile -ExecutionPolicy Bypass -File .\START_SYSTEM.ps1 -BindAddress 0.0.0.0 -Port 8080
مسئول شبکه در Windows Firewall فقط روی پروفایل Private و LocalSubnet اجازه ورودی TCP به پورت انتخاب‌شده بدهد. پروفایل Public، روتر و اینترنت را باز نکنید. هیچ تغییر firewall در این بسته خودکار نیست.
کارمندان آدرس http://آدرس_میزبان:8080 را در مرورگر باز می‌کنند؛ PHP/MySQL/Composer/npm روی کمپیوترهای آنان لازم نیست.
اگر نرسید، ساعت/شبکه، آدرس درست، روشن بودن میزبان، پورت و قانون محدود firewall را بررسی کنید.

11. اجرای دوامدار
START_SYSTEM از سرور داخلی PHP استفاده می‌کند و برای شروع و شبکه محدود مناسب است؛ سرویس وب پایدار برای بار زیاد یا امنیت HTTPS نیست.
برای استفاده روزانه دوامدار، نصب‌کننده Apache با PHP یا IIS/FastCGI و HTTPS را تنظیم کند. ریشه وب فقط public باشد. فایل public\.htaccess برای Apache موجود است. تنظیمات سرویس باید پس از restart خودکار باشد.
برای شروع ساده پس از restart Windows، ابتدا فعال بودن MySQL Service را بررسی و START_SYSTEM را دوباره اجرا کنید. هیچ پروسه پنهان یا وظیفه خودکار در این بسته نصب نمی‌شود.

12. پشتیبان
از کاربران بخواهید ثبت جاری را تمام کنند. فضای کافی و فولدر محافظت‌شده بیرون public، ترجیحاً دیسک جدا، آماده کنید.
powershell -NoProfile -ExecutionPolicy Bypass -File .\BACKUP_SYSTEM.ps1 -Destination 'E:\CompanyBackups'
مسیر نمونه را با مسیر خودتان جایگزین کنید. فرمان هنگام پشتیبان موقتاً سیستم را می‌بندد و پس از تکمیل دوباره باز می‌کند.
هر پشتیبان فولدر زمان‌دار شامل database.sql، files\private، files\public و backup.json با SHA-256 فایل‌ها است.
دیتابیس، تکت‌ها و فایل‌های بارگذاری‌شده شامل‌اند. .env، APP_KEY، رمزها به صورت فایل تنظیمات، logs، cache و source در پشتیبان نیستند. ZIP تحویلی و .env/APP_KEY نصب را جداگانه و محفوظ نگه دارید.
دیتابیس پشتیبان شامل معلومات حساس، hash رمز کاربران و sessionها است؛ آن را عمومی نسازید. MYSQL_PWD فقط به پروسه فرزند داده می‌شود، نه به فرمان چاپ‌شده. مدیر Windows هنوز باید قابل اعتماد باشد.

13. بازیابی امن
بازیابی به دیتابیس موجود/غیرخالی انجام نمی‌شود. دیتابیس قبلی را نگه دارید.
بسته را در فولدر جدا باز کنید، یک دیتابیس خالی بازیابی بسازید و حساب محدود به آن بدهید. .env بازیابی را به همین دیتابیس تنظیم کنید. فایل تنظیمات محفوظ نصب/APP_KEY را نگه دارید؛ به سیستم اصلی دست نزنید.
پیش از بازیابی migrate اجرا نکنید. فولدرهای storage\app\private و public باید خالی باشند.
powershell -NoProfile -ExecutionPolicy Bypass -File .\RESTORE_SYSTEM.ps1 -BackupFolder 'E:\CompanyBackups\backup-نام_واقعی' -Database 'نام_دیتابیس_خالی_بازیابی'
فرمان نام هدف و SHA-256 تمام فایل‌های پشتیبان را بررسی می‌کند. هدف غیرخالی، اسناد موجود یا پشتیبان ناقص رد می‌شود. دیتابیس موجود پاک نمی‌شود.
پس از بازیابی، حساب‌ها، معامله‌ها، روزنامچه و تکت خصوصی را بررسی کنید. تنها پس از تأیید مدیر، آدرس کاری را به نصب بازیابی‌شده منتقل کنید.
اگر بازیابی ناکام شد، سیستم بازیابی بسته می‌ماند؛ نصب‌کننده خطا را بررسی کند. برای تلاش بعدی هدف جداگانه خالی بسازید. سیستم اصلی را پاک نکنید.

14. رفع مشکل
php پیدا نشد: PHP 8.5 را نصب، PATH را اصلاح و PowerShell تازه باز کنید.
MySQL اجرا نیست: در Services سرویس نصب‌شده MySQL را بررسی کنید؛ سرویس‌های نامرتبط را متوقف نکنید.
خطای اتصال: DB_HOST/PORT/DATABASE و وجود دیتابیس را بررسی کنید.
نام/رمز اشتباه: حساب برنامه و صلاحیت همان schema را بررسی کنید؛ رمز root را در .env نگذارید.
پورت گرفته شده: همان سرور قبلی را پیدا کنید یا پورت آزاد دیگری برای START_SYSTEM و APP_URL انتخاب کنید. پروسه نامرتبط را نکشید.
storage permission: حساب اجرای PHP اجازه Modify روی storage و bootstrap\cache داشته باشد.
APP_KEY نیست: روی نصب تازه php artisan key:generate؛ روی نصب قبلی کلید محفوظ را برگردانید و بی‌دلیل کلید تازه نسازید.
صفحه سفید/خطا: logs را محلی بررسی کنید؛ APP_DEBUG برای استفاده واقعی false بماند. logs را بدون پوشاندن معلومات حساس شریک نسازید.
تنظیمات cache کهنه: php artisan config:clear و restart همان سرور؛ رمز را چاپ نکنید.
CSS/JS نیست: public\build\manifest.json و assets باید در بسته باشد؛ فایل public\hot نباید وجود داشته باشد.
LAN نمی‌رسد: آدرس میزبان، شبکه، Port و firewall محدود را بررسی کنید؛ به اینترنت port-forward نکنید.
رمز فراموش: مدیر عمومی از تنظیمات حساب مجاز را اصلاح کند؛ رمز پیش‌فرض یا راه دورزدن ورود وجود ندارد.
